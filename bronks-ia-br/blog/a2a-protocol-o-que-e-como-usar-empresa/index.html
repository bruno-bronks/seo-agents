Protocolo A2A: O que é, Como Funciona e Como Usar em Empresas

Publicado em novembro de 2026 · 15 min de leitura

O Protocolo A2A (Agent-to-Agent) é um dos avanços mais importantes da infraestrutura de IA de 2025–2026. Lançado pelo Google em abril de 2025 e rapidamente adotado por dezenas de empresas de tecnologia, ele define o padrão de como agentes de IA se comunicam entre si — independente do modelo, do framework ou do fornecedor que criou cada agente.

Neste artigo, explicamos o que é o A2A, como ele se diferencia do MCP (Model Context Protocol da Anthropic), quais são os casos de uso práticos para empresas brasileiras e como começar a implementar multiagentes A2A.

Resumo executivo: O A2A resolve a comunicação entre agentes. O MCP resolve a comunicação agente-ferramenta. Em um sistema multiagente empresarial real, você precisa dos dois.

O que é o Protocolo A2A?

O Protocolo A2A (Agent-to-Agent) é um padrão aberto de comunicação entre agentes de IA. Lançado pelo Google como projeto open-source em abril de 2025, o A2A define:

  • Agent Card: um documento JSON que descreve o que um agente é capaz de fazer, quais são suas habilidades, formatos de entrada/saída e como se autenticar
  • Task lifecycle: como uma tarefa é criada, delegada, processada e concluída entre dois agentes
  • Comunicação assíncrona: agentes podem enviar e receber tarefas sem precisar esperar em tempo real, usando SSE (Server-Sent Events) para atualizações de progresso
  • Autenticação e segurança: padrões abertos (OAuth, API keys) para que agentes se autentiquem mutuamente de forma segura

Em termos simples: o A2A cria um "contrato" padronizado para que um agente de IA possa dizer a outro "eu sei fazer X, você pode me pedir X" e receber essa tarefa, processá-la e devolver o resultado.

A2A vs. MCP: qual a diferença?

São protocolos complementares, não concorrentes. A analogia mais clara:

  • MCP (Anthropic): define como um agente se conecta a ferramentas (banco de dados, APIs, arquivos, código). É o protocolo agente → ferramenta.
  • A2A (Google): define como dois agentes se comunicam entre si. É o protocolo agente → agente.

Como o A2A funciona na prática: o Agent Card

Cada agente que implementa o A2A expõe um /.well-known/agent.json com seu "Agent Card" — um documento que descreve o que ele pode fazer. Exemplo simplificado de um agente de análise jurídica:

{
  "name": "Agente Jurídico Bronks",
  "description": "Analisa contratos e identifica cláusulas de risco",
  "version": "1.0.0",
  "url": "https://juridico-agent.bronks.ia.br",
  "capabilities": {
    "streaming": true,
    "pushNotifications": true
  },
  "skills": [
    {
      "id": "analyze_contract",
      "name": "Analisar Contrato",
      "description": "Analisa um contrato e retorna uma lista de cláusulas de risco",
      "inputModes": ["application/pdf", "text/plain"],
      "outputModes": ["application/json", "text/markdown"]
    }
  ],
  "authentication": {
    "schemes": ["Bearer"]
  }
}

Um agente orquestrador lê esse Agent Card, entende que pode enviar um contrato PDF e receber uma análise de riscos. A comunicação é padronizada, independente do modelo de linguagem que o Agente Jurídico usa internamente.

Como implementar A2A na sua empresa: primeiros passos

  1. Mapeie os fluxos de trabalho complexos: identifique processos que hoje envolvem múltiplos times ou etapas de aprovação. Esses são os candidatos naturais para multiagentes A2A.
  2. Escolha um framework compatível: LangChain, LangGraph, CrewAI, Google ADK e AutoGen já têm suporte nativo ao A2A. Para Claude (Anthropic), o Claude Agent SDK pode ser integrado via adaptadores A2A.
  3. Comece com 2 agentes: piloto com um agente orquestrador e um agente especializado. Meça latência, qualidade e custo antes de escalar.
  4. Defina os Agent Cards: documente claramente o que cada agente faz, quais são seus inputs/outputs e como se autentica.
  5. Implemente autenticação e logs: em uso empresarial, registre todas as chamadas A2A para auditoria e conformidade.

Perguntas frequentes sobre o Protocolo A2A

O que é o Protocolo A2A?

O Protocolo A2A (Agent-to-Agent) é um padrão aberto lançado pelo Google em abril de 2025 que define como agentes de IA se comunicam entre si: como um agente descobre o que outro pode fazer (Agent Card), como delega tarefas e como recebe os resultados — tudo de forma padronizada e independente de fornecedor.

Qual a diferença entre o Protocolo A2A e o MCP?

São complementares. O MCP (Anthropic) define como um agente se conecta a ferramentas e dados. O A2A (Google) define como dois agentes se comunicam entre si. Em um sistema multiagente, você usa MCP para dar ferramentas a cada agente e A2A para que eles colaborem.

Como o Protocolo A2A beneficia empresas?

Permite criar redes de agentes especializados que colaboram como uma equipe. Um agente de vendas pode delegar ao agente jurídico a verificação de um contrato, que por sua vez pede ao agente financeiro uma análise de crédito — tudo automaticamente. Isso permite automações muito mais sofisticadas do que um único agente conseguiria.

O A2A funciona com agentes de diferentes fornecedores?

Sim. Essa é a principal proposta do A2A: interoperabilidade. Um agente Claude (Anthropic) pode se comunicar via A2A com um agente baseado em Gemini (Google), GPT (OpenAI) ou qualquer framework que implemente o protocolo.
