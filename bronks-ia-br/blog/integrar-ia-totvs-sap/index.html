Como integrar IA ao TOTVS e SAP sem substituir o ERP

Guia prático para CTOs e diretores de TI de empresas brasileiras que querem usar IA sem abrir mão do sistema legado

Por Bronks IA  ·  27 de novembro de 2026  ·  10 min de leitura

O dilema é real: sua empresa quer usar inteligência artificial para automatizar processos, mas tem um TOTVS Protheus com dez anos de customizações ou um SAP que custou milhões para implantar. Substituir? Impossível. Não usar IA? Concorrentes não vão esperar.

A boa notícia é que você não precisa escolher. O protocolo MCP (Model Context Protocol) e as APIs modernas de ERP tornaram possível conectar agentes de IA a qualquer sistema legado — lendo dados em tempo real, executando tarefas e respondendo perguntas de negócio — sem tocar uma linha do código-fonte do ERP.

Neste guia, vamos mostrar exatamente como isso funciona para TOTVS (Protheus e Datasul) e SAP (S/4HANA e Business One), com casos de uso reais e passo a passo de implementação.

O problema: por que tantas empresas travam com IA

Conversamos com diretores de TI de médias e grandes empresas todo mês. O padrão se repete: há vontade de implementar IA, budget aprovado, até um caso de uso claro. O travamento vem quando o time de TI faz a pergunta óbvia — "mas como a IA vai acessar os dados do ERP?"

As abordagens tradicionais não funcionam bem:

  • Exportar dados para um data warehouse — funciona para relatórios, mas não para IA que precisa agir em tempo real (gerar um pedido de compra, consultar saldo de estoque no momento da venda).
  • Reescrever APIs customizadas — caro, lento e cria débito técnico. Para cada caso de uso novo, um novo desenvolvimento.
  • Aguardar o módulo de IA nativo do fornecedor — TOTVS e SAP estão lançando recursos, mas a adoção real ainda é limitada e as melhores aplicações dependem de modelos de linguagem que eles não fornecem.

A solução moderna: um conector MCP que expõe os dados e ações do ERP como "ferramentas" para o agente de IA. O agente consulta, decide e age — sem scripts frágeis, sem exportações em lote.

O que é o protocolo MCP e por que ele resolve este problema

O MCP (Model Context Protocol), lançado pela Anthropic em 2024 e adotado amplamente em 2025–2026, é um padrão aberto que define como modelos de linguagem (LLMs) se comunicam com fontes de dados externas. Em termos práticos, pense nele como um "USB para IA": você cria um servidor MCP que expõe seu ERP, e qualquer agente compatível consegue "plugar" e usar esses dados.

A arquitetura é simples:

  1. Um servidor MCP roda na sua infraestrutura (nuvem ou on-premises).
  2. Ele se conecta ao ERP via API REST, banco de dados ou conector nativo.
  3. Ele expõe "ferramentas" para o agente: consultar_estoque(produto_id), listar_pedidos_em_aberto(cliente_id), criar_pedido_compra(itens).
  4. O agente de IA decide quando chamar cada ferramenta com base no objetivo do usuário.

O resultado: o agente consegue responder "qual o prazo de entrega do pedido 45321?" consultando o TOTVS em tempo real — sem você precisar programar um único if/else.

Integração com TOTVS Protheus: como funciona na prática

O TOTVS Protheus (a versão mais usada nas médias empresas brasileiras) tem suporte a APIs REST nativas desde a versão 12.1.17. Isso significa que a maioria das instalações ativas já tem o endpoint disponível — você só precisa habilitá-lo e criar o conector MCP.

Passo 1: habilitar o REST Server no Protheus

No arquivo appserver.ini, adicione a seção [HTTPV11] com as configurações de porta e autenticação. O Protheus já vem com endpoints REST para os módulos principais: Estoque (SB1/SB2), Financeiro (SE1/SE2/SE5), Compras (SC7/SC1), RH (SRA). Não é necessário customização de código.

Passo 2: criar o servidor MCP

Um servidor MCP para TOTVS pode ser desenvolvido em Python (fastmcp) ou TypeScript (mcp-server) em 2 a 5 dias de trabalho. O servidor autentica no Protheus via Basic Auth ou OAuth 2.0, faz as chamadas REST e expõe as ferramentas padronizadas para o agente.

Passo 3: configurar o agente de IA

Com o servidor MCP rodando, você conecta o agente de IA (Claude, GPT-4o ou modelo open-source como LLaMA 3) ao servidor via configuração — sem código adicional. O agente aprende as ferramentas disponíveis no momento da inicialização.

Integração com SAP: S/4HANA e Business One

O SAP tem uma maturidade de APIs ainda maior que o TOTVS, mas com uma curva de configuração mais íngreme (e licenciamento adicional para algumas funcionalidades).

SAP S/4HANA — OData APIs e SAP Integration Suite

O S/4HANA expõe dados via OData V4 (REST). Para integração com IA, o caminho mais limpo é usar o SAP Integration Suite (antigo SAP Cloud Integration) como middleware, que já tem conectores para dezenas de sistemas. O agente de IA conversa com o Integration Suite, que por sua vez conversa com o S/4HANA. Latência de 50–300ms, adequada para interações em tempo real.

Para empresas sem Integration Suite, é possível criar um servidor MCP que chama as OData APIs diretamente usando a chave de API do SAP API Business Hub. Funciona, mas exige mais manutenção quando o SAP faz updates.

SAP Business One — SAP Service Layer

Para médias empresas com SAP Business One, o SAP Service Layer é a API REST nativa — disponível a partir da versão 9.3. É mais simples que o S/4HANA e tem documentação mais acessível. Um conector MCP para Business One pode ser desenvolvido em 3–7 dias e cobre os principais módulos: parceiros de negócio, notas fiscais, estoque e contas a pagar.

Dica prática: antes de desenvolver qualquer conector, valide se as APIs do seu ERP estão habilitadas e acessíveis. 40% dos projetos que chegam até nós travam nesta etapa — não por limitação técnica, mas por burocracia interna de TI para liberar credenciais de API.

O passo a passo de uma implantação típica

Este é o processo que a Bronks segue com clientes:

  1. Diagnóstico gratuito (1–2 dias) — mapeamos os módulos do ERP em uso, verificamos a maturidade das APIs, identificamos os 3 casos de uso de maior ROI.
  2. Desenho de arquitetura (1 semana) — definimos a stack de agentes, o escopo do conector MCP, as regras de segurança e o plano de rollout.
  3. Desenvolvimento do conector MCP (2–4 semanas) — desenvolvemos e testamos o servidor MCP com as APIs do ERP, cobrindo os módulos mapeados.
  4. Configuração e treino dos agentes (2–3 semanas) — configuramos os agentes de IA, escrevemos os system prompts, integramos com WhatsApp ou painel web interno.
  5. Piloto controlado (2 semanas) — implantação com um grupo reduzido de usuários, coleta de feedbacks, ajustes finos.
  6. Rollout completo + treinamento do time (1 semana) — implantação para todos os usuários, treinamento do time de TI para manutenção.

Erros mais comuns — e como evitá-los

Depois de dezenas de projetos, esses são os erros que mais vemos:

  • Tentar resolver tudo de uma vez — comece com um único caso de uso bem delimitado. Um agente de atendimento que responde status de pedido entrega valor em 3 semanas. Uma plataforma de IA que integra 12 módulos leva 6 meses e costuma travar.
  • Ignorar a qualidade dos dados no ERP — IA não magicamente limpa dados sujos. Se o cadastro de clientes está inconsistente no TOTVS, o agente vai perpetuar o erro. Planejar limpeza de dados como pré-requisito.
  • Dar acesso irrestrito ao ERP — o conector MCP deve ter escopo mínimo. Um agente de atendimento precisa de acesso read-only aos pedidos e NFs — não precisa criar registros ou acessar folha de pagamento.
  • Não envolver o time de TI interno — o time que mantém o ERP precisa entender a integração para suportá-la. Faça o onboarding técnico desde o início.

Perguntas frequentes

É possível integrar IA ao TOTVS sem substituir o sistema?

Sim. O protocolo MCP permite que agentes de IA se conectem ao TOTVS Protheus e Datasul via APIs REST ou conectores nativos sem alterar o código-fonte do ERP. A IA acessa dados em tempo real, executa consultas e até lança movimentos contábeis ou pedidos de compra via integração bidirecional — tudo sem migração ou substituição do sistema.

Quanto tempo leva uma integração de IA com TOTVS ou SAP?

Uma prova de conceito com um caso de uso simples pode ser entregue em 2 a 4 semanas. Uma implantação completa com múltiplos agentes e casos de uso (financeiro, compras, RH) leva de 2 a 4 meses. O prazo depende da maturidade das APIs do ERP e da complexidade dos processos a integrar.

Qual a diferença de integrar IA com TOTVS vs SAP?

TOTVS Protheus usa APIs REST nativas desde a versão 12. O SAP S/4HANA tem o SAP Integration Suite e as OData APIs — mais robustos, mas com licenciamento adicional. SAP Business One é mais acessível para médias empresas via SAP Service Layer. A arquitetura de integração é similar em ambos: um conector MCP expõe os dados do ERP para o agente de IA.

Quais casos de uso de IA funcionam melhor com ERP legado?

Os casos de maior ROI são: agente de atendimento ao cliente (consulta status de pedido no ERP), agente de compras (monitora estoque mínimo e abre pedidos automaticamente), agente financeiro (conciliação bancária e identificação de divergências), agente de RH (responde dúvidas sobre contracheque e férias) e relatórios executivos gerados em linguagem natural.

A integração de IA com ERP é segura? E a LGPD?

Sim, quando bem arquitetada. O agente de IA não armazena dados do ERP — ele consulta em tempo real via conector seguro (OAuth 2.0 ou chave de API com escopo mínimo). Para LGPD, recomendamos conector com acesso read-only para campos sensíveis, logs de todas as consultas do agente e dados de PF processados em infraestrutura nacional.
