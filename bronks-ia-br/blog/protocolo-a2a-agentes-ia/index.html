Protocolo A2A do Google: O Que É e Como Impacta a IA Empresarial no Brasil

Publicado em 24 de outubro de 2026 · 12 min de leitura · Equipe Bronks IA

Em abril de 2025, o Google anunciou o protocolo A2A (Agent-to-Agent) — um padrão aberto para comunicação entre agentes de inteligência artificial. Ao lado do MCP (Model Context Protocol) da Anthropic, o A2A representa uma virada no desenvolvimento de sistemas multiagentes: a transição de arquiteturas proprietárias e isoladas para um ecossistema interoperável onde agentes de diferentes fornecedores colaboram como equipes de pessoas.

Para empresas brasileiras que já investem em IA ou estão começando agora, entender o A2A é estratégico. Neste artigo, explicamos o que é o protocolo, como ele funciona na prática, qual a diferença em relação ao MCP, e o que muda para quem constrói ou contrata sistemas de agentes de IA.

O que é o protocolo A2A?

O A2A é uma especificação técnica aberta que define como agentes de IA se descobrem, se comunicam e colaboram. Antes do A2A, se você quisesse que um agente de CRM conversasse com um agente de ERP e ambos acionassem um agente de análise de dados, precisava construir adaptadores customizados para cada par de sistemas — um trabalho de integração caro e frágil.

O A2A resolve esse problema com três conceitos centrais:

1. Agent Card (Cartão do Agente)

Cada agente compatível com A2A publica um Agent Card — um arquivo JSON acessível via URL que descreve o que o agente sabe fazer: suas capacidades, as tarefas que aceita, os tipos de entrada e saída esperados, e como se autenticar para usá-lo. É como um currículo padronizado que qualquer agente orquestrador pode ler e entender automaticamente.

2. Task Protocol

O A2A define um protocolo de tarefas estruturado: o agente cliente cria uma Task, o agente servidor a processa e retorna atualizações de status (working, completed, failed) e artefatos (o resultado da tarefa — texto, código, arquivo, formulário preenchido). A comunicação pode ser síncrona (espera o resultado) ou assíncrona com streaming de eventos.

3. Multi-Modal Content

O A2A suporta nativamente múltiplos tipos de conteúdo nas mensagens entre agentes: texto, JSON estruturado, imagens, arquivos, formulários interativos e até widgets de interface. Isso permite que um agente entregue não só dados mas experiências completas para outros agentes ou para o usuário final.

Em resumo: o A2A é o "protocolo de colaboração" entre agentes, enquanto o MCP é o "protocolo de ferramentas". Um agente usa MCP para acessar um banco de dados; usa A2A para solicitar que outro agente especialista processe aqueles dados.

A2A vs. MCP: qual a diferença e como se complementam?

A confusão entre A2A e MCP é comum — ambos são protocolos abertos para IA agêntica, mas resolvem problemas diferentes:

Aspecto MCP (Anthropic) A2A (Google)
O que define Como agentes se conectam a ferramentas e dados Como agentes se comunicam entre si
Analogia Agente ↔ Ferramentas de trabalho Agente ↔ Colegas de equipe
Exemplo de uso Agente consulta banco de dados via MCP Agente orquestrador delega análise a agente especialista via A2A
Principais adotantes Claude, VS Code, Cursor, Zed SAP, Salesforce, ServiceNow, Google Workspace
Compatíveis entre si? Sim — um agente pode usar MCP e A2A simultaneamente

Na prática, um sistema multiagente empresarial moderno usa ambos: MCP para que cada agente acesse seus sistemas específicos (CRM, ERP, banco de dados), e A2A para que os agentes se coordenem e deleguem tarefas entre si.

Quem já adota o A2A?

O Google lançou o A2A como protocolo aberto no Google Cloud Next 2025, com uma lista inicial de mais de 50 parceiros anunciando suporte. Entre os principais:

  • SAP: integração com SAP Joule (agente de IA corporativo) para comunicação com agentes de parceiros via A2A
  • Salesforce: Agentforce aceita e emite tarefas A2A com outros agentes no ecossistema Salesforce e externo
  • ServiceNow: Now Assist usa A2A para orquestrar agentes de ITSM com sistemas externos
  • Atlassian: Rovo (agente da Atlassian) expõe capacidades via A2A para integração com ferramentas de desenvolvimento
  • LangChain e LangGraph: suporte nativo ao A2A para frameworks de desenvolvimento de agentes open-source
  • Google Workspace: agentes de Gemini no Gmail, Docs e Meet se comunicam via A2A com agentes de terceiros

O que muda na prática para empresas brasileiras?

Para quem está desenvolvendo ou contratando sistemas de IA no Brasil, o A2A tem implicações práticas que já estão chegando em 2026:

1. Redução do custo de integração entre sistemas

A maior barreira para IA empresarial no Brasil não é o custo dos modelos — é o custo de integração com sistemas legados. Com o A2A, qualquer agente compatível pode se comunicar com qualquer outro sem adaptadores customizados. Para uma empresa que usa SAP + Salesforce + um chatbot customizado, isso pode reduzir o custo de integração em 40% a 60%.

2. Agentes especializados como "serviços" contratáveis

O A2A abre caminho para um mercado de agentes especializados: assim como hoje você contrata uma API de CEP ou de nota fiscal, em breve será possível contratar um agente especialista em análise jurídica de contratos, um agente de classificação fiscal de produtos ou um agente de análise de crédito — e conectá-lo ao seu orquestrador via A2A sem necessidade de customização profunda.

3. Portabilidade e redução de lock-in

Com arquiteturas A2A, trocar o modelo de IA subjacente de um agente (de GPT para Claude, por exemplo) não requer reescrever os agentes vizinhos — a interface A2A permanece a mesma. Isso reduz o lock-in de fornecedor e aumenta o poder de negociação das empresas.

4. Governança e rastreabilidade em sistemas multiagentes

O A2A define uma trilha de tarefas rastregável: cada delegação entre agentes é registrada com ID de tarefa, timestamps e status. Para empresas em setores regulados (financeiro, saúde, jurídico), isso facilita a conformidade com exigências de auditoria e explicabilidade — você sabe exatamente qual agente tomou qual decisão em qual momento.

Atenção: o A2A ainda é um protocolo em evolução. Em 2026, a versão 0.2 está estável para produção, mas atualizações significativas são esperadas para 2027. Implemente com abstração adequada para facilitar a atualização futura sem reescrever a lógica de negócio.

Como a Bronks IA usa A2A nos projetos de clientes

Na Bronks IA, já adotamos o A2A em projetos de clientes que constroem sistemas multiagentes — particularmente em setores jurídico, financeiro e logístico, onde a delegação de tarefas entre agentes especializados é central para o design da solução.

Em um projeto típico com A2A, a arquitetura segue este padrão:

  1. Agente orquestrador recebe a solicitação do usuário (via chat, API ou sistema interno)
  2. O orquestrador consulta os Agent Cards dos agentes disponíveis para identificar qual agente especialista pode resolver a subtarefa
  3. O orquestrador cria uma Task A2A e a delega ao agente especialista (análise de documento, consulta ao ERP, geração de relatório)
  4. O agente especialista processa e retorna o artefato via A2A ao orquestrador
  5. O orquestrador consolida os resultados e entrega a resposta ao usuário final

Esse padrão permite que o sistema cresça adicionando novos agentes especialistas sem modificar o orquestrador ou os outros agentes — uma arquitetura extensível por design.

Compatibilidade com MCP: em todos os projetos com A2A, usamos MCP em paralelo. Os agentes especialistas usam MCP para acessar ferramentas (banco de dados, APIs, sistemas legados), e o A2A para receber tarefas do orquestrador. As duas especificações convivem naturalmente na mesma arquitetura.

O A2A vai substituir as arquiteturas proprietárias atuais?

A transição será gradual. A maioria das empresas brasileiras que já tem agentes em produção usa frameworks como LangChain, CrewAI ou AutoGen com integrações customizadas. Migrar para A2A não é obrigatório agora — mas a tendência é clara: à medida que os grandes fornecedores de ERP, CRM e plataformas SaaS adotam o padrão, a pressão para compatibilidade vai crescer.

Nossa recomendação: para projetos novos de multiagentes, construa com A2A desde o início — o custo marginal é baixo e os benefícios de longo prazo são significativos. Para sistemas existentes, planeje uma migração incremental, agente por agente, priorizando os pontos de integração mais caros de manter.

Perguntas frequentes sobre o protocolo A2A

O que é o protocolo A2A do Google?
O A2A (Agent-to-Agent) é um protocolo aberto lançado pelo Google em abril de 2025 para padronizar a comunicação entre agentes de IA de diferentes fornecedores. Ele define como um agente descobre as capacidades de outro (via Agent Card), como delega tarefas e como troca mensagens estruturadas.
Qual a diferença entre A2A e MCP?
O MCP define como um agente acessa ferramentas e dados externos; o A2A define como agentes se comunicam entre si. São complementáres: um sistema multiagente típico usa ambos — MCP para ferramentas, A2A para colaboração entre agentes.
O protocolo A2A já é adotado no Brasil?
Em 2026, o A2A está em adoção inicial. Grandes fornecedores como SAP, Salesforce e ServiceNow já implementaram suporte. No Brasil, empresas de consultoria como a Bronks IA já constroem sistemas compatíveis, mas a adoção generalizada em PMEs ainda está no início.
Como o A2A beneficia empresas que já usam IA?
O A2A reduz o custo de integração entre sistemas de IA, facilita a troca de fornecedores sem reescrever os agentes vizinhos, e permite comprar agentes especialistas de fornecedores diferentes sem lock-in de plataforma.
