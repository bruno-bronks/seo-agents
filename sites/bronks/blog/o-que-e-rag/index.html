O que é RAG, explicado de forma simples

Imagine que você contratou o melhor consultor do mundo — alguém com conhecimento enciclopédico sobre negócios, tecnologia e estratégia. O problema: ele não conhece nada sobre a sua empresa específica. Não sabe o conteúdo dos seus contratos, os procedimentos internos, as políticas de atendimento ou os dados dos seus clientes.

É exatamente esse o problema que o RAG resolve.

RAG (Retrieval-Augmented Generation) é uma arquitetura que combina dois componentes: um sistema de recuperação de documentos (retrieval) e um modelo de geração de texto (como GPT-4 ou Claude). Antes de responder uma pergunta, o sistema busca os trechos mais relevantes dos seus documentos e os apresenta como contexto para o modelo. O resultado é uma resposta gerada com base nos seus dados reais.

Em português: RAG é a tecnologia que faz o ChatGPT "saber" o que está nos seus documentos, sem você precisar enviar tudo para a OpenAI ou treinar um novo modelo.

Como o RAG funciona tecnicamente

O RAG opera em duas fases principais: a fase de indexação (feita uma vez) e a fase de consulta (feita a cada pergunta).

📥

1. Ingestão de documentos

Seus documentos (PDFs, Word, e-mails, páginas web, dados de banco de dados) são carregados no sistema e processados.

✂️

2. Chunking (divisão em pedaços)

Cada documento é dividido em pedaços menores (chunks), geralmente de 200 a 1.000 tokens. O tamanho ideal depende do tipo de conteúdo.

🔢

3. Geração de embeddings

Cada chunk é convertido em um vetor numérico (embedding) por um modelo de embedding. Esse vetor captura o significado semântico do texto.

🗄️

4. Armazenamento no banco vetorial

Os vetores são armazenados em um banco de dados vetorial (como Pinecone, Weaviate, Chroma ou pgvector). Isso permite buscas por similaridade semântica.

🔍

5. Recuperação (Retrieval)

Quando o usuário faz uma pergunta, ela também é convertida em vetor. O sistema busca os chunks mais similares no banco vetorial.

🤖

6. Geração aumentada (Augmented Generation)

O modelo de linguagem recebe a pergunta original + os chunks recuperados como contexto, e gera uma resposta fundamentada nos seus documentos.

RAG vs. fine-tuning: qual escolher?

Uma dúvida comum: quando usar RAG e quando usar fine-tuning? São abordagens diferentes com casos de uso distintos.

Critério RAG Fine-tuning
O que ensina ao modelo Dados externos em tempo real (seus documentos) Estilo, formato e padrão de resposta
Custo de implementação Baixo a médio Alto (GPU, dados rotulados, tempo)
Atualização de dados Instantânea (re-indexa o novo documento) Requer novo ciclo de treinamento
Citação de fontes Sim (aponta qual documento embasou a resposta) Não (o modelo não sabe de onde veio)
Alucinações Menor risco (resposta baseada em contexto real) Maior risco
Melhor para Q&A sobre documentos, assistentes de atendimento, wikis internas Mudança de tom, terminologia específica, formato de saída

Regra prática: para a maioria das aplicações empresariais que envolvem acesso a documentos internos, RAG é a escolha certa. Fine-tuning faz sentido quando você precisa mudar o comportamento do modelo, não o conhecimento dele.

🏥

Consulta de prontuários

Clínicas usam RAG para consultar histórico do paciente e protocolos clínicos durante o atendimento.

🧮

📞

📊

Consulta de relatórios

Executivos fazem perguntas em linguagem natural sobre relatórios financeiros e recebem respostas com citação de fonte.

Como implementar RAG na sua empresa

Implementar RAG do zero requer conhecimento de LLMs, bancos de dados vetoriais, engenharia de prompts e infraestrutura em nuvem. O stack típico de produção envolve:

  • Modelo de embedding: text-embedding-3-large (OpenAI), voyage-3 (Anthropic/Voyage) ou modelos open source como nomic-embed-text
  • Banco vetorial: Pinecone, Weaviate, Qdrant, Chroma ou pgvector (PostgreSQL)
  • Modelo de geração: GPT-4o, Claude 3.5 Sonnet, Llama 3 (self-hosted)
  • Framework de orquestração: LangChain, LlamaIndex, ou implementação própria
  • Pipeline de ingestão: parsers para PDF, Word, HTML, dados estruturados
  • Avaliação (RAG eval): RAGAS, TruLens ou métricas próprias de faithfulness e relevância

Além do stack técnico, é necessário cuidado com a qualidade dos dados indexados (garbage in, garbage out), a estratégia de chunking (que varia por tipo de documento) e os testes com queries reais antes de ir para produção.

Quanto custa implementar RAG?

Projetos de RAG empresarial na Bronks IA variam conforme o volume de documentos, número de usuários e integrações necessárias. Um projeto piloto (1 base de conhecimento, até 10 mil documentos, integração com um canal de acesso) tipicamente fica entre R$ 15.000 e R$ 45.000 com entrega em 4 a 8 semanas. O custo operacional mensal de APIs e infraestrutura tende a ser baixo para volumes B2B.

Conclusão

RAG é hoje a arquitetura mais eficiente e custo-efetiva para dar ao seu modelo de IA acesso ao conhecimento interno da sua empresa. Comparado ao fine-tuning, é mais barato, mais atualizado, mais transparente (cita fontes) e mais seguro para dados sensíveis.

Se você tem documentos, manuais, contratos ou dados que sua equipe precisa consultar frequentemente, RAG provavelmente é a solução.
